# 飞书（Lark / 妙搭）接入指南

> 状态：已支持 · 本文面向自部署管理员
> 能力声明见 `backend/app/integrations/feishu/adapter.py`；实现细节见 `backend/app/services/feishu.py`

## 1. 简介

飞书是途排智策当前支持度最完整的外部平台集成。管理员在设置页一次填写企业自建应用凭据并授权后，系统自动创建并管理排课多维表格，不需要手工创建任何数据表或复制表格标识。

### 能力矩阵

| 能力 | 支持情况 | 说明 |
| --- | --- | --- |
| 表格存储 | ✔ | 多维表格自动建表、字段对账、按业务 ID 幂等同步；公开投影（展示汇总/调课通知/班级链接索引）自动维护 |
| 日历 | ✔ | 教师忙闲查询（freebusy）+ 课表日程创建，即「日历下发」 |
| 通知 | ✔* | 能力已声明；独立消息推送的消费接缝在二期收敛（当前站内通知已覆盖提醒场景） |
| 审批 | ✔* | 能力已声明；平台审批代理提交在二期收敛（当前发布审批由系统内审批流承担） |
| 自然语言 | ✔ | 一句话排课默认走**平台无关**的 OpenAI-compatible 模型通道（设置 → AI 模型）；飞书 Aily Workflow 为**可选**高级通道，未配置不影响任何功能 |

> \* 通知与审批为 manifest 能力上限声明（`Capability.NOTIFIER` / `Capability.APPROVAL`）。v1 实际消费接缝为表格存储、日历与自然语言，其余按二期路线逐个收敛（见 `backend/app/integrations/README.md` 接缝迁移路线）。

## 2. 前置条件

- **飞书企业自建应用**：在[飞书开放平台](https://open.feishu.cn/app/)创建；个人版与商店应用不适用本流程。
- **飞书管理权限**：能在开放平台为该应用申请权限、修改安全设置并发布版本（通常需要组织管理员配合）。
- **途排智策管理员账号**：应用凭据录入与 OAuth 授权由 `admin` 角色完成。
- **网络可达**：后端需能访问 `open.feishu.cn` 与 `accounts.feishu.cn`；浏览器需能访问飞书授权页并回跳到后端回调地址。
- 可选：如需一句话排课功能，另行准备任一 OpenAI-compatible 模型接口（接口地址 + API Key + 模型名），与飞书应用无关。

## 3. 所需权限清单

以下均为**用户身份（user_access_token）权限**，在开放平台「权限管理」中按中文名搜索申请。前 15 项为多维表格链路，后 3 项为「日历下发」链路。

### 多维表格（10 张业务表同步）

| 权限键 | 开放平台名称 | 用途 | 必需性 |
| --- | --- | --- | --- |
| `offline_access` | 持续访问已授权的数据 | 换取刷新令牌，令牌过期后自动续期 | 必需 |
| `base:app:create` | 创建多维表格 | 自动创建排课多维表格 | 必需 |
| `base:app:read` | 获取多维表格信息 | 读取表格与字段做同步预检 | 必需 |
| `base:table:create` | 新增数据表 | 自动创建业务表 | 必需 |
| `base:table:read` | 获取数据表信息 | 同步前字段对账 | 必需 |
| `base:table:update` | 更新数据表 | 表改名（如默认空表改为「接入说明」） | 必需 |
| `base:field:read` | 读取数据表字段 | 字段对账 | 必需 |
| `base:field:create` | 新增数据表字段 | 升级旧表时补齐新增字段 | 必需 |
| `bitable:app:readonly` | 读取多维表格应用与字段 | 读取 Base 元数据 | 必需（与 `bitable:app` 二选一） |
| `bitable:app` | 管理多维表格应用与字段 | 完整权限，可替代以上细分权限 | 可选（替代方案） |
| `base:record:create` | 新增记录 | 写入主数据与课表记录 | 必需 |
| `base:record:retrieve` | 根据条件搜索记录 | 同步前记录对账（幂等键匹配） | 必需 |
| `base:record:update` | 更新记录 | 覆盖更新已有记录 | 必需 |
| `base:record:delete` | 清理系统生成的重复记录 | 删除系统拥有的过期/重复公开投影 | 可选（缺失时跳过清理，主同步不受影响） |
| `base:view:write_only` | 创建/更新视图 | 维护「课表」表上的班级筛选视图 | 可选（缺失时跳过视图同步） |

### 日历（「日历下发」功能）

| 权限键 | 开放平台名称 | 用途 | 必需性 |
| --- | --- | --- | --- |
| `calendar:calendar.event:create` | 创建日程 | 为课次创建教师日程 | 使用日历下发时必需 |
| `calendar:calendar.event:update` | 更新日程 | 添加日程参与人使用该权限 | 使用日历下发时必需 |
| `calendar:calendar.free_busy:read` | 读取日历忙闲信息 | 下发前检查教师忙闲冲突 | 使用日历下发时必需 |

要点：

- 只申请细分权限时，至少保留 `bitable:app:readonly`（读取 Base/字段）和 `base:field:create`（升级旧表补字段）。
- **不需要**「多维表格插件」——该插件用于把自定义视图嵌入表格，不是服务端 OpenAPI 的前置条件。
- 权限、重定向地址或刷新令牌设置发生变化后，**必须发布应用新版本才生效**。

## 4. 配置步骤

全部操作在途排智策 **设置 → 外部集成 → 飞书（Lark / 妙搭）** 卡片完成，点击「接入向导」进入五步引导（首次进入设置页会自动弹出）。飞书后台操作与设置页步骤一一对应：

### 第 1 步 · 配置企业自建应用

| 设置页 | 飞书开放平台 |
| --- | --- |
| 填写应用编号（`cli_...`）与应用密钥，保存（后端自动生成加密主密钥，密钥加密存储、页面不回显明文） | 创建企业自建应用，获取凭据 |
| 复制页面自动生成的**授权回调地址** | 「安全设置 → 重定向 URL」中添加该地址，格式为 `https://你的后端域名/api/v1/integrations/feishu/oauth/callback` |
| 对照页面内嵌的权限清单逐项申请 | 「权限管理」中申请第 3 节所列权限 |
| — | 「应用发布 → 版本管理与发布」创建并发布版本；可用范围覆盖实际使用的管理员与教务人员 |

也可以不经过页面，用环境变量 `FEISHU_APP_ID` / `FEISHU_APP_SECRET` / `FEISHU_OAUTH_REDIRECT_URI` 完成应用配置引导（页面会显示「当前配置由部署环境统一管理」）。

### 第 2 步 · 配置一句话排课 AI

在「AI 模型（OpenAI-compatible）」分区填写**接口地址、API Key、模型名称**（例如豆包 Ark、DeepSeek 或企业自有模型网关）。注意：

- 接口地址填到**版本根路径**（如 `https://provider.example/v1`），系统会自动拼接 `/chat/completions`。
- API Key 只提交给本地后端并加密保存，页面不回显。
- 该步与飞书应用无关，可跳过（仅影响一句话排课，不影响表格/日历链路）。

### 第 3 步 · 授权飞书管理员账号

点击「授权飞书管理员账号」后：

1. 后端生成一次性 `state`，浏览器跳转飞书授权页；
2. 管理员确认授权，飞书回调后端；
3. 后端校验 `state`，用授权码换取 v3 用户令牌，**Fernet 加密**保存 `user_access_token`、一次性轮换的 `refresh_token`、有效期与实际授予的权限范围；
4. 页面显示「管理员账号已授权」，并给出访问令牌到期时间。

多维表格将创建在该管理员的飞书云空间，归属授权管理员本人。

### 第 4 步 · 创建排课多维表格

输入排课空间名称（系统会自动附加当前课表方案名，第 1、2、……N 套课表各自绑定独立多维表格），点击「自动创建排课表格」。后端使用管理员令牌：

1. 创建多维表格，记录 `app_token`、默认表与 `url`；
2. 把默认空表改名为「接入说明」（标明系统、学校、学期、创建人、创建时间）；
3. 自动创建 10 张中文业务表：教师、班级、教室、时段、课程场次、规则、课表、公开展示汇总、公开调课通知、班级链接索引（建表时直接带上中文字段）；
4. 保存后端资源与飞书 `table_id` 的绑定，页面展示「打开多维表格」入口。

创建中断后重试同一空间名会**补齐缺失业务表**，不会新建另一套课表。

### 第 5 步 · 同步业务数据

- **一键同步当前方案**：写入顶栏当前所选方案绑定的多维表格（10 类数据），只同步、不触发求解；
- **重试单表**：批量同步按资源独立落日志，某张表失败不影响其他表，可单独重试；
- 发布或回滚课表版本后自动同步当前版本；旧版本与版本差异保留在本地数据库，飞书侧只保留当前运行投影。

同步幂等性：以「课表方案 + 课程场次业务 ID」为稳定业务标识，重复同步只更新同一行；只清理系统拥有的重复/过期公开投影，不会删除管理员手工新增的记录。

## 5. 测试连接

v1 的「测试连接」为**只读本地配置检查**（`FeishuAdapter.verify()`），不发外部网络请求；设置页的实时连接状态来自 `GET /api/v1/integrations/feishu/connection`，即飞书卡片顶部的状态徽章：

| 徽章 | 后端状态 | 含义 | 处理 |
| --- | --- | --- | --- |
| 已连接（绿） | `connected` | 应用已配置、已授权、权限齐备、多维表格就绪 | 可正常同步 |
| 未配置（黄） | `unconfigured` | 尚未保存应用凭据 | 完成第 1 步 |
| 待授权（黄） | `not_authorized` | 应用已配置，尚未完成 OAuth 授权 | 完成第 3 步 |
| 需重新授权（红） | `reauthorization_required` | 授权过期、刷新令牌失效或缺少所需权限 | 见故障排查第 1 条 |
| 配置中（黄） | （前端兜底态） | 已授权但业务表未建齐或缺少同步权限 | 按卡片内「同步暂不可用原因」清单补齐 |

卡片内的「飞书生产连接」摘要面板还给出五项细分检查：应用配置、一句话排课 AI、管理员账号、排课多维表格、业务数据表（N / 10 张）。

## 6. 故障排查

### 6.1 权限变更后同步仍失败（`missing_scopes` 非空 / 返回错误码 `99991679`）

**症状**：开放平台已勾选新权限，但设置页仍提示缺少权限，同步报「当前用户令牌没有所需权限」。
**原因**：旧 `user_access_token` 不会因刷新页面或普通令牌刷新自动获得新增权限。
**解决**（顺序执行）：在开放平台**发布应用新版本** → 途排智策点击**解除连接** → **重新授权管理员账号** → 再同步。重新授权完成后，连接详情的「已授予权限 / 缺少权限」才会更新。

### 6.2 授权回调失败（state 校验不通过）

**症状**：授权跳转后回程报「飞书授权未完成，请重新发起授权」。
**原因**：`state` 是一次性防重放参数（浏览器回退重放会失败）；或开放平台「重定向 URL」与设置页展示的回调地址不一致（协议、域名、路径任一不符）。
**解决**：核对重定向 URL 与设置页完全一致后重新发起授权；不要通过浏览器回退重试回调。

### 6.3 「日历下发」返回 409「请先在当前页面填写飞书应用编号和应用密钥」

**原因**：进入忙闲查询前系统会协商日历能力（`registry.has_capability(Capability.CALENDAR)`）；飞书应用未配置时无可用日历集成。
**解决**：完成第 1、3 步；并确认教师主数据已填写「日历账号」（`calendar_user_id`）——未映射的教师课次会被跳过（页面上体现为 `skipped_unmapped`）。

### 6.4 教师忙闲数据缺失

**原因**：飞书忙闲接口 `POST /open-apis/calendar/v4/freebusy/list` 一次只接受一个用户，**不存在**批量端点。系统自动按每批 10 个教师、14 天窗口逐用户调用后汇总（见 `backend/app/api.py` 的日历下发实现）；该分片是本项目的自我约束，不是官方限制。
**解决**：确认对应教师已配置日历账号且其日历对授权管理员可见。

### 6.5 一句话排课报 404 或返回非 JSON 内容

**原因**：AI 接口地址误填到控制台页面（如 `.../console`）而非接口版本根路径（如 `.../v1`）。系统在地址后拼接 `/chat/completions`，控制台地址会拼出无效端点。
**解决**：在设置 → AI 模型把接口地址改为模型服务商文档标注的 API 根路径。

### 6.6 PKCE 相关报错（错误码 20049，仅限自行改造授权链路时）

飞书自建应用是 Confidential Client（`client_secret` 必填），官方授权码流程默认不使用 PKCE；本项目也已移除 PKCE 参数、仅保留 `state` 防 CSRF（依据官方文档 2026-08 复核）。若自行加回 `code_challenge` 而令牌端点持续返回 20049「PKCE code challenge failed」，移除 PKCE 参数即可。

### 6.7 班级视图或重复记录清理未执行

**症状**：同步结果中提示「班级视图未创建」「发现 N 条历史重复记录；补充清理权限后可自动删除」。
**原因**：可选权限 `base:view:write_only` / `base:record:delete` 未申请。这两项缺失时主数据同步仍能完成。
**解决**：开放平台补充对应权限 → 发布新版本 → 重新授权 → 重试同步。

### 6.8 解除连接后飞书侧还有数据

「解除连接」删除本地保存的令牌密文、工作区绑定、表绑定和记录绑定；**已创建的多维表格仍保留在管理员云空间**。当前官方契约不包含令牌撤销端点，系统不宣称远程撤销飞书侧授权；需要彻底撤销时，请在飞书的「应用授权管理」中取消该应用授权。

## 7. 已知限制

| 类别 | 限制 |
| --- | --- |
| 分批与限频 | 记录搜索每页 500 条；批量新增/更新每批 1,000 条；公开投影删除每批 500 条。读取/更新/删除网络临时错误最多重试 2 次，新增在响应丢失时先对账再重试 |
| 视图 | 「课表」表按班级维护筛选视图（每班一个、按排序键升序），视图数量随班级数线性增长；缺少 `base:view:write_only` 时视图同步自动跳过，不影响数据同步 |
| 妙搭公开链接 | 公开分享 URL 无法由 API 直接生成：管理员需首次在多维表格开启独立分享（或发布妙搭公开应用）后，把最终 URL **回填**到「班级链接索引」；后续同步保留这些手工字段。普通视图入口 ≠ 互联网公开分享，务必以未登录身份实测 |
| Lark 国际版 | manifest 已预留「base_url 切换 Lark 国际版」的描述，但当前代码中 `open.feishu.cn` / `accounts.feishu.cn` 域名为常量（`services/feishu.py` 头部 `OPEN_API_URL` / `AUTHORIZATION_URL` / `TOKEN_URL`），国际版切换尚需代码适配，暂未开放 |
| 时区 | 业务日期时间与飞书日历字段统一按 `Asia/Shanghai`（UTC+8）处理；令牌过期检查内部使用 UTC 瞬间 |
| 数据归属 | 默认资源归属授权管理员个人。组织要求应用统一持有中央资源时，需另行实现基于 `tenant_access_token` 的组织级模式，两模式不混用 |
| 同步记录 | 设置页展示最近 50 次同步；日志含批次、读写量、耗时、重试次数、飞书请求日志 ID 与失败原因，不含任何完整令牌 |
