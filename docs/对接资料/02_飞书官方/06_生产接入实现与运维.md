# 飞书生产接入实现与运维

代码基线：2026-08-16

## 应用内配置

普通生产接入由管理员在前端一次填写 `App ID` 和 `App Secret`。前端根据当前后端地址
生成 OAuth 回调地址，根据当前页面生成授权完成返回地址；后端校验后将凭据保存到
`feishu_app_configurations`。

`App Secret` 使用 Fernet 加密，默认主密钥首次保存时自动生成到
`data/secrets/feishu.key`，该目录不进入 Git。主密钥需要与数据库一起备份；主密钥丢失后，
已保存的应用密钥和用户令牌需要重新录入或授权。

生产容器或集中密钥管理平台可以用 `FEISHU_APP_ID`、`FEISHU_APP_SECRET`、
`FEISHU_TOKEN_ENCRYPTION_KEY`、`FEISHU_OAUTH_REDIRECT_URI` 和 `FRONTEND_URL` 覆盖数据库
配置。环境配置优先级更高，启用后前端只读，适用于 KMS 注入场景，不属于普通管理员流程。

页面生成的 OAuth 回调地址必须与飞书开放平台安全设置中的重定向 URL 完全一致。
系统自动创建多维表格，不配置 `app_token` 或数据表标识。

## 应用内接口

| 方法 | 路径 | 角色 | 用途 |
| --- | --- | --- | --- |
| GET | `/api/v1/integrations/feishu/connection` | 已登录用户 | 查看应用配置、授权、权限和工作区状态 |
| POST | `/api/v1/integrations/feishu/app-configuration` | 管理员 | 加密保存应用编号、应用密钥和自动生成的回调地址 |
| POST | `/api/v1/integrations/feishu/oauth/start` | 管理员 | 生成一次性 `state` 和飞书授权地址 |
| GET | `/api/v1/integrations/feishu/oauth/callback` | 飞书回调 | 校验状态、交换用户令牌并返回前端 |
| POST | `/api/v1/integrations/feishu/workspaces` | 管理员 | 创建或续建排课多维表格和 10 张默认业务表 |
| DELETE | `/api/v1/integrations/feishu/connection` | 管理员 | 删除本地令牌密文与全部飞书绑定 |
| POST | `/api/v1/integrations/feishu/sync` | 管理员、排课员 | 将指定业务资源幂等同步到当前课表方案 |
| POST | `/api/v1/integrations/feishu/sync-batch` | 管理员、排课员、审批人 | 批量同步当前课表方案的请求资源；每个资源独立落日志 |
| GET | `/api/v1/integrations/feishu/syncs` | 已登录用户 | 查看最近 50 次同步记录 |
| GET | `/api/v1/overview/analytics` | 可查看当前课表方案的用户 | 教师负荷、教室时段热力、软约束质量和飞书同步健康 |

OAuth 回调不要求携带途排智策 JWT。回调通过一次性 `state` 定位发起授权的用户；`state` 只在数据库保存 SHA-256。客户端认证使用 `client_secret`，不使用 PKCE（依据见契约核对记录的 2026-08-13 联调记录）。

所有工作区、表绑定、记录绑定和同步日志都带 `schedule_set_id`。每套课表方案拥有独立的飞书
工作区；管理员可管理全部方案，其他用户必须同时满足全局角色与该方案的成员权限。账号列表中的
方案授权是唯一管理入口，不再维护第二套独立“课表访问权限”页面。

连接状态有 `unconfigured`、`not_authorized`、`connected` 和 `reauthorization_required` 四种。
当令牌过期、刷新失败、权限不足或飞书返回 `99991679` 时，服务端保存错误原因并标记
`reauthorization_required`；同步失败详情会带 `reauthorization_required=true`。管理员需要在飞书
控制台发布带新权限的应用版本，然后在前端执行“解除连接 → 重新授权管理员账号”，不能只刷新页面。

## 持久化表

| 数据表 | 保存内容 |
| --- | --- |
| `feishu_app_configurations` | 应用编号、应用密钥密文、回调地址、前端地址和配置人 |
| `feishu_oauth_states` | 用户、状态哈希、过期时间、使用时间 |
| `feishu_connections` | 访问令牌密文、刷新令牌密文、有效期、权限和连接状态 |
| `feishu_workspaces` | 多维表格名称、`app_token`、默认表、链接和创建状态 |
| `feishu_table_bindings` | 后端资源、中文表名和飞书 `table_id` |
| `feishu_record_bindings` | 业务标识和飞书 `record_id` |

数据库升级：

```powershell
cd backend
uv run alembic upgrade head
```

## 自动创建和恢复

1. 创建多维表格后立即保存工作区，状态为“创建中”。
2. 将默认表改名为“接入说明”。
3. 依次创建教师、班级、教室、时段、课程场次、规则、课表、公开展示汇总、公开调课通知、班级链接索引（共 10 张）。
4. 每成功创建一张表立即保存绑定。
5. 中途失败时工作区记录错误；管理员再次使用同名空间执行创建会从缺失的数据表继续。
6. 全部完成后状态切换为“已启用”，前端开放同步。

所有业务表第一列均为“业务标识”。课表标识由“课表方案 + 场次 ID”组成，当前发布版本覆盖同一场次的旧行；
“班级链接索引”按“课表方案 + 班级稳定 ID”一班一行。旧版“班级公开课表”不再进入默认同步。

## 妙搭与班级入口

- `课表` 是课程明细源表；系统按稳定班级标识维护班级筛选视图。
- `班级链接索引` 是入口目录，不复制课程明细。管理员在妙搭应用首次发布后，将学生/家长入口链接回填到“学生/家长妙搭链接”字段。
- “公开视图链接”用于保存该班级的多维表格视图入口；视图首次对外分享仍需在飞书界面完成，后续同步保留手工回填的 URL。
- 每次发布/回滚会先同步 `课表`、汇总和通知，再更新链接目录；班级消失时不会追加新行。
- “一键同步当前方案”只做数据投影，不创建 `SolverRun`，也不生成新的课表版本。

## 幂等同步

每次同步按以下顺序执行：

1. 先完成一次 Base/数据表/字段预检；同一批次只做一次元数据读取，并自动接管名称匹配的旧表。
2. 分页读取飞书现有记录（每页 500 条），把富文本形态的“业务标识”规范化后建立索引。
3. 选择每个业务标识的 canonical `record_id`；缺失业务标识进入批量新增（每批 1,000 条），已有标识进入批量更新（每批 1,000 条）。
4. `schedule` 的业务标识与版本号无关（课表方案 + 场次业务 ID），发布 V2 时覆盖 V1；历史版本仍保留在本地版本表，不追加到运行投影。
5. 对 `schedule`、`public_summary`、`public_class_schedule`、`public_adjustment_notice`、`public_class_links` 等系统拥有的公开投影，删除不再属于当前投影的重复、过期和无业务标识记录（删除每批 500 条）。删除只针对本地绑定台账可确认或系统生成的记录；缺少 `base:record:delete` 时记录 `skipped_missing_delete_scope`，主同步仍可完成。
6. 对账并修复本地业务标识与 `record_id` 绑定；新增记录响应丢失时重新读取并按业务标识对账，禁止盲目重放 `batch_create`。
7. 保存远端已有数、新增数、更新数、跳过数、删除数、重复清理状态、视图同步状态、请求日志 ID 和错误。

同步请求使用短超时与有限重试：读取/更新/删除最多重试 2 次，新增在响应丢失时先对账再重试。
批量同步不是全有或全无事务；每个资源单独写入 `integration_syncs`，最终返回 `completed`、`partial`
或 `failed`，可据结果只重试失败资源。

当前只开放“途排智策到飞书”的生产同步。飞书人工修改回写业务数据库需要先冻结字段所有权、冲突处理和审批规则，未实现的回写入口不会显示在前端。

## 令牌与故障处理

- 访问令牌到期前 2 分钟自动刷新。
- 默认单进程 SQLite 使用进程内连接锁；PostgreSQL 同时使用数据库行锁。锁内重新检查有效期，刷新成功后在同一事务中替换访问令牌和一次性刷新令牌。
- 刷新令牌过期或飞书拒绝刷新时，连接状态变为“需要重新授权”。
- 网络请求失败只记录错误，保留连接供后续重试。
- 自动建表失败保留已创建的工作区和数据表绑定，再次执行同名创建可续建。
- 解除连接删除本地密文和绑定，不删除管理员飞书云空间中的表格。

所有业务数据库时间、API 响应时间和公开投影更新时间统一为 `Asia/Shanghai`（UTC+8）。令牌有效期、
OAuth `state` 过期和 JWT 校验在内部用 UTC 瞬间比较；不要把数据库中带 UTC+8 的业务时间再按 UTC
重复转换。飞书日历事件的 `timezone` 明确写为 `Asia/Shanghai`。

## 班级入口与视图运维

- `课表` 保存当前发布版本的课程明细；同步成功后按 `班级标识` 创建/维护 `班级｜...` 网格视图，
  视图按“排序键”升序，并隐藏内部标识，仅保留班级、日期、时间、课程、学科、教室和版本字段。
- 视图维护是可选投影：缺少 `base:view:write_only`（或完整 `bitable:app`）时，课表记录仍会同步，
  返回的 `view_sync.status` 为 `skipped_missing_scope`，补权限并重新授权后可再次生成。
- `班级链接索引` 每班一行，保存学生/家长妙搭 URL、公开视图 URL、访问模式、状态、失效时间和备注。
  这些管理员手工字段不能被发布/回滚同步清空；远端管理员填写的公开 URL 优先于系统生成的
  普通视图入口。首次分享视图的最终公开 URL 仍需在飞书界面完成后回填。
- 旧版 `班级公开课表` 不再进入默认批量同步。已有历史明细应先备份，再执行一次兼容压缩或清理，
  后续学生入口统一使用 `课表` 班级视图和 `班级链接索引`。

## 验证范围

后端定向测试覆盖：

- 授权地址、`state` 单次使用和回调重放拦截。
- 管理员从前端保存应用凭据、密文不回显、自动生成本地主密钥。
- 访问令牌与刷新令牌密文保存。
- 刷新令牌轮换后旧值不再保留。
- 自动创建 10 张中文业务表，首列固定为“业务标识”；班级链接索引按班级稳定 ID 一行一条。
- 同名工作区重复创建不产生第二个多维表格。
- 同一批教师数据同步两次后，飞书记录数不增加，第二次走批量更新。
- 9000 条级别的课表按 500 条分页读取、1000 条批量写入；公开投影清理按 500 条批量删除，不再固定 200 条。
- V1/V2 发布、回滚和手工重复同步都复用同一业务标识，不会每次新增一整套课程记录。

## 总览分析统计

`GET /api/v1/overview/analytics` 以当前课表方案的已发布版本为统计基线，支持 `date_from`、
`date_to` 和 `sync_window_hours` 查询参数：

| 统计块 | 口径 | 前端建议 |
| --- | --- | --- |
| `teacher_workload` | 按校区+教师标识隔离，以课程实际 `duration_minutes` 汇总节数和小时；输出 Top 5 和负荷区间 | 直方图、教师负荷榜 |
| `room_heatmap` | `cells` 提供星期×课节明细，`period_cells` 提供周一至周日×上午/下午/晚自习固定 7×3 汇总；缺失日期边界从版本课次补齐 | 7×N 或 7×3 热力图 |
| `optimization_penalties` | 最近一次求解的目标值、best bound、求解课次范围内的可解释扣分与满足率；返回范围来源和对账差额 | 进度条、扣分条形图 |
| `sync_health` | 最近窗口内同步数、成功/失败数、读写量、平均耗时、重试次数和最近同步时间 | 同步健康卡片 |

接口是只读统计，不触发求解、发布、回滚或飞书写入。没有发布版本/历史分项时返回空集合和
明确状态，禁止用估算值伪装成真实软约束满足率。
