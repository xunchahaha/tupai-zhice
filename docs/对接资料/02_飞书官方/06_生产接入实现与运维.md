# 飞书生产接入实现与运维

代码基线：2026-08-10

## 部署配置

后端只保存以下飞书应用级配置：

```text
FEISHU_APP_ID=cli_xxx
FEISHU_APP_SECRET=应用密钥
FEISHU_TOKEN_ENCRYPTION_KEY=Fernet密钥
FEISHU_OAUTH_REDIRECT_URI=https://后端域名/api/v1/integrations/feishu/oauth/callback
FRONTEND_URL=https://前端域名
```

加密密钥生成命令：

```powershell
uv run python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"
```

`FEISHU_OAUTH_REDIRECT_URI` 必须与飞书开放平台安全设置中的重定向 URL 完全一致。生产环境不得使用开发默认密钥，不配置 `app_token` 或数据表标识。

## 应用内接口

| 方法 | 路径 | 角色 | 用途 |
| --- | --- | --- | --- |
| GET | `/api/v1/integrations/feishu/connection` | 已登录用户 | 查看应用配置、授权、权限和工作区状态 |
| POST | `/api/v1/integrations/feishu/oauth/start` | 管理员 | 生成一次性 `state`、PKCE 参数和飞书授权地址 |
| GET | `/api/v1/integrations/feishu/oauth/callback` | 飞书回调 | 校验状态、交换用户令牌并返回前端 |
| POST | `/api/v1/integrations/feishu/workspaces` | 管理员 | 创建或续建排课多维表格和 7 张业务表 |
| DELETE | `/api/v1/integrations/feishu/connection` | 管理员 | 删除本地令牌密文与全部飞书绑定 |
| POST | `/api/v1/integrations/feishu/sync` | 管理员、排课员 | 将指定业务资源幂等同步到飞书 |
| GET | `/api/v1/integrations/feishu/syncs` | 已登录用户 | 查看最近 50 次同步记录 |

OAuth 回调不要求携带途排智策 JWT。回调通过一次性 `state` 定位发起授权的用户；`state` 只在数据库保存 SHA-256，PKCE verifier 使用同一独立密钥加密保存。

## 持久化表

| 数据表 | 保存内容 |
| --- | --- |
| `feishu_oauth_states` | 用户、状态哈希、PKCE verifier 密文、过期时间、使用时间 |
| `feishu_connections` | 访问令牌密文、刷新令牌密文、有效期、权限和连接状态 |
| `feishu_workspaces` | 多维表格名称、`app_token`、默认表、链接和创建状态 |
| `feishu_table_bindings` | 后端资源、中文表名和飞书 `table_id` |
| `feishu_record_bindings` | 业务标识和飞书 `record_id` |

数据库升级：

```powershell
cd backend
uv run alembic upgrade head
```

## 自动创建和恢复

1. 创建多维表格后立即保存工作区，状态为“创建中”。
2. 将默认表改名为“接入说明”。
3. 依次创建教师、班级、教室、时段、课程场次、规则、课表。
4. 每成功创建一张表立即保存绑定。
5. 中途失败时工作区记录错误；管理员再次使用同名空间执行创建会从缺失的数据表继续。
6. 全部完成后状态切换为“已启用”，前端开放同步。

所有业务表第一列均为“业务标识”。课表标识由“版本 ID + 场次 ID”组成，历史发布版本继续保留，“是否当前版本”字段用于区分当前版本。

## 幂等同步

每次同步按以下顺序执行：

1. 分页读取飞书现有记录。
2. 检查飞书侧和本地待同步数据是否存在重复业务标识；存在重复时停止写入并记录失败。
3. 缺失业务标识进入批量新增。
4. 已有业务标识根据 `record_id` 进入批量更新。
5. 对账并修复本地业务标识与 `record_id` 绑定。
6. 保存远端已有数、新增数、更新数、写入数和飞书请求日志 ID。

当前只开放“途排智策到飞书”的生产同步。飞书人工修改回写业务数据库需要先冻结字段所有权、冲突处理和审批规则，未实现的回写入口不会显示在前端。

## 令牌与故障处理

- 访问令牌到期前 2 分钟自动刷新。
- 默认单进程 SQLite 使用进程内连接锁；PostgreSQL 同时使用数据库行锁。锁内重新检查有效期，刷新成功后在同一事务中替换访问令牌和一次性刷新令牌。
- 刷新令牌过期或飞书拒绝刷新时，连接状态变为“需要重新授权”。
- 网络请求失败只记录错误，保留连接供后续重试。
- 自动建表失败保留已创建的工作区和数据表绑定，再次执行同名创建可续建。
- 解除连接删除本地密文和绑定，不删除管理员飞书云空间中的表格。

## 验证范围

后端定向测试覆盖：

- 授权地址、PKCE S256、`state` 单次使用和回调重放拦截。
- 访问令牌与刷新令牌密文保存。
- 刷新令牌轮换后旧值不再保留。
- 自动创建 7 张中文业务表，首列固定为“业务标识”。
- 同名工作区重复创建不产生第二个多维表格。
- 同一批教师数据同步两次后，飞书记录数不增加，第二次走批量更新。
