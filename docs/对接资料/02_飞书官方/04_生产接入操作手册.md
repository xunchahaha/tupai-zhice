# 途排智策飞书生产接入操作手册

当前方案版本：2026-08-16

## 结论

生产主流程采用“企业自建应用 + 前端一次录入应用凭据 + 飞书 OAuth 用户授权 + 服务端 OpenAPI 自动建表”。管理员在途排智策填写 `App ID` 和 `App Secret` 后，后端加密保存；随后授权飞书账号，系统自动创建多维表格、业务数据表和字段，并保存表格链接及全部标识。

手工填写 `app_token` 和各表 `table_id` 只作为未来“接管既有多维表格”的高级入口，不属于首次接入流程。

## 一次性的应用配置

该部分由系统管理员完成一次，不需要登录服务器或修改 `.env`。

1. 在[飞书开放平台](https://open.feishu.cn/app/)创建企业自建应用。
2. 登录途排智策，进入“飞书集成”，在第一步填写 `App ID` 和 `App Secret`。后端自动生成加密主密钥，加密保存 `App Secret`，页面不回显明文。
3. 复制途排智策页面自动生成的地址，在飞书“安全设置 -> 重定向 URL”中添加：

   ```text
   https://你的后端域名/api/v1/integrations/feishu/oauth/callback
   ```

4. 在权限管理申请以下用户身份权限（左侧为权限键，右侧为开放平台控制台中的官方名称，可直接按中文名搜索）：

   ```text
   offline_access          持续访问已授权的数据
   base:app:create         创建多维表格
   base:app:read           获取多维表格信息
   base:table:create       新增数据表
   base:table:read         获取数据表信息
   base:table:update       更新数据表
   base:field:read        读取数据表字段
   base:field:create      新增数据表字段
   bitable:app:readonly   读取多维表格应用元数据（与 bitable:app 二选一即可）
   bitable:app            管理多维表格应用与字段（可替代细分权限）
   base:record:create      新增记录
   base:record:retrieve    根据条件搜索记录
   base:record:update      更新记录
   base:record:delete      清理系统生成的重复记录
   base:view:write_only    创建/更新班级筛选视图（可选）
   ```

   `bitable:app` 是完整权限；如果只申请细分权限，至少要保留 `bitable:app:readonly`（用于
   读取 Base/字段）和 `base:field:create`（升级旧表时补字段）。`base:record:delete` 与
   `base:view:write_only` 分别只影响重复/过期投影清理和班级视图维护，不影响主数据的新增、读取、更新。

   若要使用「教师日历下发」，再申请以下三项日历权限（依据见
   `05_官方契约核对记录_2026-08-10.md` 的 2026-08-15 复核）：

   ```text
   calendar:calendar.event:create    创建日程
   calendar:calendar.event:update    更新日程（添加日程参与人使用该权限）
   calendar:calendar.free_busy:read  读取日历忙闲信息
   ```

5. 将应用可用范围覆盖实际使用途排智策的管理员和教务人员。
6. 创建并发布应用版本。权限、重定向地址和刷新令牌设置发生变化后都要重新发布才生效。

> 权限变更后必须执行“发布应用新版本 → 解除途排智策旧连接 → 重新授权管理员账号”。
> 旧 `user_access_token` 不会因为刷新网页或普通令牌刷新自动获得新增权限。

不需要为这条链路添加“多维表格插件”。该插件用于把自定义视图嵌入某张多维表格，不是服务端 OpenAPI 的前置条件。

## 管理员首次接入

1. 管理员登录途排智策，进入“飞书集成”。
2. 一次填写 `App ID` 和 `App Secret`，保存应用配置。
3. 将页面给出的回调地址加入飞书开放平台，申请页面列出的用户身份权限并发布应用版本。
4. 点击“授权飞书管理员账号”。
5. 后端生成一次性 `state`，把浏览器跳转到飞书授权页。
6. 管理员确认授权后，飞书回调后端；后端校验 `state`，再用授权码交换 v3 用户令牌。
7. 后端加密保存 `user_access_token`、一次性轮换的 `refresh_token`、有效期和实际授予的权限范围。
8. 前端显示“账号已授权”，并进入“创建排课多维表格”步骤。

如果连接页显示“需要重新授权”、`missing_scopes` 非空，或同步返回飞书错误码 `99991679`，
请按“发布应用新版本 → 途排智策点击解除连接 → 点击重新授权管理员账号 → 再同步”的顺序处理。
旧 `user_access_token` 不会因刷新页面或单纯刷新令牌而获得新权限；重新授权完成后，连接页的
`granted_scopes`/`missing_scopes` 才会更新。

## 自动创建排课空间

管理员点击“创建排课多维表格”后，后端使用其 `user_access_token`：

1. 创建名为“途排智策 - 学校 - 学期”的多维表格。
2. 记录返回的 `app_token`、`default_table_id` 和表格 `url`。
3. 将创建接口附带的默认空表改名为“接入说明”，用于标明系统、学校、学期、创建人和创建时间。
4. 自动创建教师、班级、教室、时段、课程场次、规则、课表、公开展示汇总、公开调课通知和班级链接索引 10 张业务表；创建表时直接带上中文字段。
5. 保存后端资源与飞书 `table_id` 的绑定。
6. 在前端显示“打开多维表格”按钮和建表结果，不展示让用户复制标识的输入框。

默认资源归属于授权管理员。若组织以后要求应用统一持有中央资源，再增加基于 `tenant_access_token` 的组织级部署模式，两个模式不混用。

## 发布与同步

发布课表时：

1. 后端校验课表版本已完成审批且硬冲突为 0。
2. 以“课表方案 + 课程场次业务 ID”作为课表记录的稳定业务标识；版本号只作为字段展示。
   因此 V2 发布会更新 V1 对应的同一行，不会把整张课表再次追加一遍。
3. 查询已有记录，新增缺失项、更新已有项，并只清理系统拥有的重复/过期投影；不会删除管理员
   自己新增的非系统记录。
4. 旧版本和版本差异保留在途排智策本地数据库；飞书“课表”只保留当前运行投影，旧行由同一业务标识覆盖或作为过期投影清理。
5. 同步日志保存请求批次、读写数量、耗时、重试次数、飞书请求日志 ID 和失败原因，不保存完整 Token。
6. 成功后返回多维表格 URL，管理员可直接打开查看。

“一键同步当前方案”只同步当前已发布方案，不会再次调用求解器；求解必须由排课员单独提交
`POST /api/v1/solver-runs`。批量同步先做一次 Base/字段预检，再分别记录每个资源的结果，因此
某一张表失败不会吞掉其他已成功的表。记录搜索分页为每页 500 条，批量新增/更新每批 1,000 条，
系统拥有的过期/重复公开投影删除每批 500 条；网络临时错误最多重试 2 次。

### 班级入口目录

“班级链接索引”每个班级仅保留一行，登记学生/家长妙搭链接和该班多维表格公开视图链接。
妙搭建议使用一个公开应用，通过班级稳定 ID 筛选“课表”明细；不要为每节课复制一份公开入口。
访问模式、状态、失效时间和备注由管理员维护，发布/回滚同步会保留这些手工字段。

链接索引的唯一业务键是“课表方案 + 班级稳定 ID”，不是班级名称。系统在 `课表` 明细表上
维护每班筛选视图并按 `排序键` 升序。管理员首次在多维表格开启独立分享、或首次发布妙搭
公开应用后，把最终 URL 回填到索引表；后续同步保留这些手工链接。

主数据同步同样使用业务 ID 幂等更新。飞书侧人工修改是否回写业务数据库需要单独配置数据治理规则，不能把“读到预览”当成完成导入。

## 断线与撤销

- `user_access_token` 到期前由后端使用 `refresh_token` 自动刷新。
- 每次刷新必须原子替换新 `refresh_token`；并发刷新按连接加锁。
- 管理员撤销授权或失去应用使用权限后，连接状态显示“需要重新授权”，不继续尝试写入。
- “解除连接”会立即删除途排智策保存的令牌密文、工作区绑定、数据表绑定和记录绑定；已创建的多维表格仍由管理员保留。
- 当前冻结的官方契约没有包含令牌撤销端点，因此“解除连接”不宣称远程撤销飞书侧授权。需要彻底撤销时，管理员同时在飞书的应用授权管理中取消该应用授权。

## 前端引导应呈现的步骤

1. 填写并保存开放平台应用凭据。
2. 授权飞书账号。
3. 创建排课多维表格。
4. 检查 10 张业务表和权限。
5. 发布首个课表版本。

前端总览可直接调用 `GET /api/v1/overview/analytics` 获取教师课时负荷分布、教室×时段热力、
软约束扣分/满足率和最近 24 小时飞书同步健康；该接口只读当前已发布版本，不触发求解。

主界面只显示可执行动作、当前状态和修复入口。`App Secret` 只提交一次，用户令牌、`app_token` 和 `table_id` 都由后端管理。

## 排课日期与时间说明

- `date_from`、`date_to` 是本次求解选中的原始课次日期范围（含边界），同时裁剪每节课的候选日期窗口。
- `date_window_days` 是未锁定课次围绕原始日期允许前后移动的天数，默认 7 天，范围 0–31；锁定课次只能留在原日期。
- `time_limit_seconds` 是求解器运行上限（1–900 秒）。超时只返回当前状态和目标界，不自动发布。
- 教室不重叠、教师不重叠是后端自动补齐的系统硬约束，调用方不能通过删掉 `solver_rules` 来关闭。
- 业务日期时间和接口响应统一显示 `Asia/Shanghai`（UTC+8）。OAuth/JWT 令牌过期检查在内部使用 UTC
  瞬间，进入业务响应或飞书日历字段时才转换为 UTC+8。

## 旧版“班级公开课表”迁移

升级前若已有旧表和数千条课程明细，升级代码不会继续把它列入默认同步。首次上线后先手工备份，
确认“课表”的班级筛选视图和“班级链接索引”已可用，再在飞书中归档或清空旧表。当前公开同步
请求不再暴露 `public_class_schedule`，不要把旧表重新加入“一键同步当前方案”，也不要在新旧两张表
同时维护学生入口。
