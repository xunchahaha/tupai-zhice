# 后端接口与运行约定

实现基线：2026-08-16  
机器可读契约：`backend/openapi.json`

本文只记录当前代码已经实现的业务边界。请求/响应字段的最终类型、必填项和状态码以同一提交
生成的 OpenAPI 为准。

## 通用约定

- API 前缀：`/api/v1`
- 登录：OAuth2 password flow，后续请求使用 `Authorization: Bearer <JWT>`
- 当前课表方案：`X-Schedule-Set-Id: <schedule_set_id>`
- Aily 服务端调用：`X-Aily-Key`
- 业务日期：`YYYY-MM-DD`
- 业务时间：`Asia/Shanghai`（UTC+8），带时间的请求必须包含时区偏移
- 错误体：FastAPI 标准 `detail`；批量接口会在资源级结果中保留失败原因

当用户只有一套可见课表时，普通登录接口可使用该方案；存在多套课表时，前端必须显式传
`X-Schedule-Set-Id`。Aily 请求在多方案场景同样必须传该请求头。

## 课表方案与成员权限

| 方法 | 路径 | 权限 | 说明 |
| --- | --- | --- | --- |
| GET | `/schedule-sets` | 已登录 | 返回当前用户可见方案及当前发布版本 |
| POST | `/schedule-sets` | 管理员 | 新建任意数量的课表方案 |
| PATCH | `/schedule-sets/{id}` | 管理员 | 修改方案名称 |
| GET | `/schedule-sets/{id}/members` | 管理员 | 查看方案成员 |
| PUT | `/schedule-sets/{id}/members/{user_id}` | 管理员 | 授予 `viewer`/`scheduler`/`approver` |
| DELETE | `/schedule-sets/{id}/members/{user_id}` | 管理员 | 撤销该方案访问 |

权限规则：

- `admin` 默认管理全部方案，不需要成员记录；
- 方案权限不能高于账号全局角色；
- 停用账号不能获得方案权限；
- 一个排课员可以拥有方案 1，也可以同时拥有方案 1、2、3……；
- 工作区、主数据、求解、版本、审计和飞书同步全部按 `schedule_set_id` 隔离。

## 导入与主数据

- 示例模板：`GET /imports/sample.xlsx`
- 模板直通导入：`POST /imports/xlsx`
- 智能导入预览：`POST /imports/preview`（管理员）
- 智能导入提交：`POST /imports/commit`（管理员）
- 主数据：`/campuses`、`/teachers`、`/class-groups`、`/rooms`、`/time-slots`、
  `/course-sessions`、`/rules`

导入器严格按官方 14 列表头读取，不按列位置猜测。课件名称、编排阶段、产品班型、班级标签
是不同语义，导入预处理完成后才落库；修改同一课次再次导入按稳定业务键更新，源表删除项按
引用关系清理或报告。

### 智能映射导入（L2）

面向任意教务导出的 XLSX/CSV（≤64MB），两步走：

| 步骤 | 请求 | 说明 |
| --- | --- | --- |
| 预览 | `POST /imports/preview`，multipart：`file` + 可选 `mapping_json` + 可选 `cell_overrides` | 返回 `sheets`、`header_candidates`、`mapping`（逐列 `column/column_index/target/confidence/rationale/matched_by/sample_values`）、`issues`（行级校验，`行号`+`原因`）、`stats`，以及 `historical_match` / `ignored_overrides`。只解析不落库。 |
| 提交 | `POST /imports/commit`，multipart：`file` + `mapping_json`（必填）+ `mode=insert\|upsert` + 可选 `cell_overrides` | 按确认的映射入库，响应与模板直通导入同构，另附 `mode`、`course_sessions_updated`、`course_sessions_skipped_existing`、`overrides_applied`、`ignored_overrides`。 |

约定与语义：

- `mapping_json` 结构：`{"sheet": "工作表名|null", "header_row_index": 0-based 行号|null, "columns": [{"column": "表头文本", "column_index": 0-based 列号|null, "target": "规范字段|null"}]}`。`target=null` 表示该列不导入；用户指定的映射一个字段只允许对应一列。
- 历史映射记忆（historical mapping）：预览不带 `mapping_json` 时，把当前表头序列规范化（复用归一化层）后取 sha256 指纹（列序敏感，调列序/增删列即视为新表），按 `schedule_set_id + 指纹` 查 `import_mapping_history`。命中则按上次 commit 生效的映射（含手动修正与「不导入」决策）直接预填：`matched_by="historical"`、置信度 0.95、`historical_match=true`，且跳过 AI 语义提名。commit 成功后 upsert 本次生效映射（`used_count` 累加），失败导入不记忆；历史只在同一课表方案内复用，坏记录整份弃用退回自动建议。
- 单元格原地修复（cell_overrides）：preview/commit 均接受可选表单字段 `cell_overrides`，JSON 形如 `{"<sheet 内 1-based 行号>": {"<表头文本或规范字段名>": "<新值>"}}`，在解析后、校验前原地改写单元格（与 `issues` 的 `行号` 同口径）。行号不存在（超界/指向表头行）或列名解析不到的条目忽略并计入 `ignored_overrides`，生效数计入 `stats.overrides_applied`；结构不合法（非对象、数组值等）整体 422。commit 与最后一次校验 preview 必须携带同一份 `cell_overrides`，前端向导在错误清零（`rows_skipped=0`）后才放行提交。
- 映射置信度 < 0.5 的列返回 `target=null`（不硬猜）；四层匹配 = 别名表/精确 → 归一化（全半角/空白/大小写）→ 编辑相似度 → 前 20 行样本形状校验；AI 接口已配置时对未匹配列追加语义提名（可关闭，未配置自动跳过）。
- `mode=upsert` 沿用业务键（班级+课次序号+课节名称+上课日期+上课时段）重复导入即更新并清理源表已删除项；`mode=insert` 只新增，已存在课次原样保留，不做孤儿清理。
- 行级校验与入库复用模板导入的同一条核心管线，跳过行/占位教室/质量报告口径一致。
- `column_index`、`header_row_index` 均为 0-based 网格下标；CSV 支持 UTF-8（带 BOM）与 GBK 编码。
- 错误码：非 XLSX/CSV 文件 400；`mapping_json` 不合法、列不存在、一个字段被多列占用、无法识别表头行、`cell_overrides` 结构不合法 422；文件超限 413。

## 求解

主要接口：

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/solver-runs` | 创建手动求解任务；可选 `goal_id` 关联持久目标（MEM-C3），run 到达 completed 后自动验收 |
| GET | `/solver-runs` | 列表（含 `goal_id`、`goal_report`） |
| GET | `/solver-runs/{id}` | 详情、解释和诊断 |
| GET | `/solver-runs/{id}/events` | SSE 进度 |
| POST | `/assistant/interpret` | 自然语言转结构化范围/规则；响应附 `goal_checklist_draft` + `checklist_warnings`（可增删项后再创建 goal） |
| POST | `/assistant/interpret/stream` | 同上的 SSE 流式版本（见下节） |
| POST | `/assistant/solve` | 使用已确认结构启动同一 CP-SAT 流程；可选 `goal_id` 关联目标；可选 `parent_schedule_id`（显式基准版本，优先于目标工作草稿与最新已发布版本）与 `course_business_ids`（目标课次） |
| POST | `/goals` | 创建持久目标（MEM-C3）：`instruction` 必填，`checklist` 缺省时按结构化范围字段确定性生成（业务范围→coverage、日期→date_range_match、`forbidden_slots`→逐条禁排项、`forbid_publish`(默认 true)→draft_only、`max_changes`+`baseline_schedule_version_id`→变更上限项）。**底线验收（MEM-D2 + MEM-E2/E2b）强制并入且不可删**：`deliverable_exists`、`no_hard_conflicts`、`no_duplicate_lessons`（交付课次不重复，不依赖范围），有明确目标集合（课次/班级/业务线/班型）时的 `coverage`（携带完整规范化范围参数）；响应含 `acceptance_status`/`acceptance_detail` |
| GET | `/goals` | 目标列表（状态/清单项数/关联 run 数） |
| GET | `/goals/{id}` | 目标详情：runs 历史（各 run 带自己的 `goal_report`）+ `latest_report` + `checklist_history`（清单修订快照，只读） |
| POST | `/goals/{id}/abandon` | 人工放弃（终态；再次放弃 409，已放弃目标拒绝关联新求解任务 409） |
| PATCH | `/goals/{id}/checklist` | 整体替换验收清单（MEM-D3 + MEM-E2/E2a + MEM-F/F3）：body 为完整 `checklist` 数组 + 可选 `scope`。**scope 三态语义（按字段是否在 body 里显式出现判定，pydantic `model_fields_set` 口径）：未提交=保留旧值（无旧值则该维度无限制）；显式空列表 / 显式 `null` 日期=清除该维度限制；显式非空=替换新值。显式 scope 优先于清单 coverage 既有参数**（完整清单里旧 coverage 参数也会被显式 scope 覆盖）。kind 白名单、key 唯一、底线项强制并入——复用创建校验；每次保存把旧清单快照进 `checklist_history`；响应返回新清单 + `checklist_version`（= 历史长度+1）+ `latest_report_meta`（旧结论所属版本标注）。修订使既有验收结论失效：`acceptance_status` 回 pending（detail=「清单修订至 v{n}，等待新验收」）、`status` 为 achieved 回退 open。已放弃目标 409、跨方案 404 |

关键参数：

- `date_from`、`date_to`：选择原始课次日期范围，并裁剪候选日期边界；两端均包含；
- `date_window_days`：每节未锁定课次相对原日期允许前后移动的天数，范围 `0–31`；
- `time_limit_seconds`：求解时限，范围 `1–900` 秒；
- `wait=false`：入队后台执行；`wait=true`：请求内执行；
- `change_weight`：调课时尽量保留旧安排的权重；
- `solver_rules`：可选系统规则，但 `room_no_overlap`、`teacher_no_overlap` 始终由后端补齐。

求解完成生成草稿版本，不自动发布。超时只返回求解器实际状态、目标值和 best bound，不能表述为
“已求得最优”。预检无解与 CP-SAT 证明无解分别通过 `presolve_infeasible` 区分。

### 目标验收闭环（MEM-C3，正确性口径 MEM-D2）

- **checklist kind ↔ 验收器**：`deliverable_exists`（底线：run 存在非空课表产物）、
  `coverage`（课次集合逐项比对；缺口区分「未进求解范围」→ 建议修正范围重跑、
  「进了范围未安置」→ 等待教务；**重复检测**：同一课次在交付课表出现 ≥2 次判
  failed）、`forbidden_slot_free`（主体+时段独立复核；`needs_params=true` 的占位项
  在参数补齐前恒不通过；执行前先按方案主数据核对 subject/slot 存在性，不存在 →
  unverifiable「禁排对象不存在，请补齐参数」）、`no_hard_conflicts`（底线：
  `count_hard_conflicts` 独立重算）、`no_duplicate_lessons`（底线，MEM-E2/E2b：
  交付课次不重复——同一课次在交付课表出现 ≥2 次即 failed，不依赖目标范围，
  无范围清单的查重兜底）、`max_changes`（对基准版本 diff，只设上限——
  优化类目标，「尽量少改」不升级为「绝不改」）、`draft_only`（审计日志核对目标
  期间无 `publish`/`calendar_publish`）、`date_range_match`（结果日期端点核对）。
- **三集合口径（MEM-D2/D4a）**：`date_range_match`/`coverage`/`forbidden_slot_free`
  只核对 **目标课次 ∪ 本次求解课次**（`solved_course_business_ids` 在合并回填前
  冻结，保留原样的旧课次不算越界/违规）；`no_hard_conflicts` 用合并交付课表
  （全局资源冲突看全集）。
- **无法验证 ≠ 通过（MEM-D2/D4b）**：日期缺失、课次无 slot、参数无法解析、无课表
  等情况 → 该项 `passed=false` 且 `verdict="unverifiable"`（detail 说明缺什么），
  不因「没检测到越界」判通过；`all_passed` 要求所有项 passed=true 且无
  unverifiable。
- **底线验收（MEM-D2/D4c，MEM-E2/E2b 修订）**：创建/修订目标时强制并入
  `deliverable_exists`、`no_hard_conflicts`、`no_duplicate_lessons`（交付课次
  不重复——同一课次在交付课表出现 ≥2 次即 failed，不依赖范围），以及有明确
  目标集合时的 `coverage`（params 带 `bottom_line=true`，前端「底线」徽标）；
  底线不可删除，附加清单与底线并列验收。补全传递**完整规范化范围**
  （`normalize_goal_scope`）：补入的 coverage 携带可解析的范围参数，不再用
  has_target_set 布尔；修订时按 MEM-F/F3 三态语义合并——**显式 scope 优先于
  清单 coverage 既有参数**，未提交字段保留旧 coverage 参数、显式空列表/null
  清除该维度、显式非空替换（`merge_coverage_scope`）；补全后统一校验最终清单
  key 唯一（重复 422）。
- **清单版本绑定（MEM-E2/E2a）**：`run.goal_report.meta.checklist_version` 记录
  本次验收所用清单版本（= 历史长度+1，与响应 `checklist_version` 同口径），
  `meta.checklist_snapshot` 记录当时 coverage 参数快照；`create_solver_run`
  冻结 `request_payload.goal_checklist_version`，验收时清单若又修订过，
  meta 附 `solve_checklist_version` + `version_note`（「求解参数基于 v{m} 清单
  生成，验收按 v{n}」）。修订清单（PATCH）使既有验收结论失效：acceptance_status
  回 pending、achieved 回退 open，历史报告保留但 PATCH 响应以
  `latest_report_meta.is_current_version=false` 标注；前端 pending 显示
  「等待新验收（v{n}）」，历史 run 徽标「v{n} 结论」。**写回前版本复核
  （MEM-F/F2）**：验收写回阶段在事务内重读当前 `_checklist_version`，与报告
  评估版本不一致（验收按 v1 计算、写回前清单已修订至 v2）时，报告仅作历史
  保存且 meta 标注 `evaluated_checklist_version`/`current_checklist_version`，
  `acceptance_status` 保持 pending（detail=「清单已修订至 v{n}，本报告基于
  v{m}，需重新验收」），`goal.status` 不得写 achieved。
- **报告结构**（`SolverRun.goal_report`）：`items[]`（逐项
  `key/requirement/kind/passed/verdict/bottom_line/detail/evidence`）+ `all_passed` +
  `unverifiable_count` + `gaps[]`（缺口定位、`next_step` 建议动作、`remedy` 分类）
  + `decision.status/reason`。
- **决策消费求解状态（MEM-D2/D6）**：`decision` 文案按三态分开——UNKNOWN（含
  超时）→「预算与诊断决定是否继续」，目标保持 open；INFEASIBLE（presolve 预检
  除外，不能表述为已证明无解）→「已证明无解」进 awaiting_decision；有可行解但有
  缺口 → 逐项处理。
- **验收状态（MEM-D2/D6）**：`GoalResponse.acceptance_status`
  （pending/completed/failed）+ `acceptance_detail`——run completed 先置 pending，
  验收成功 → completed，验收异常/求解失败 → failed 且原因入库（另在
  `run.goal_report` 写 `acceptance_status:"failed"` + `acceptance_error` 失败标记，
  供前端停止轮询并展示「验收失败：原因」）。
- **状态机**：`open`（进行中，附允许的补救动作）→ `achieved`（全部通过；draft_only
  目标在合格草稿交付即达成，发布永远不在目标自动动作里）/`awaiting_decision`
  （存在必须由教务放宽或裁决的缺口）/`abandoned`（人工终态）。状态永远反映最近
  一次验收；验收器只出报告，**绝不自动重跑**。
- `POST /solver-runs` 的 `goal_id` 指向已放弃目标返回 409；跨方案 goal_id 返回
  404（防探测）。
- **目标连续性（MEM-D3）**：重新解析不再清空已绑定的 goalId（同一会话沿用，
  解析口径与目标清单不一致时在确认卡以提示条说明「已关联目标 #N，清单可继续
  修订」）；手动求解 `POST /solver-runs` 携带会话持有的 `goal_id`（无目标时为
  null，行为不变）；solver 页支持 `?goal=<id>` 深链绑定（goals 页「继续处理 →
  修正范围后重新求解」跳转用）；选基准版本时创建清单自动附带 `max_changes`
  项（params.baseline=所选版本，上限默认 50，仅设验收上限不改变求解行为）。
- **清单修订与历史（MEM-D3）**：`PATCH /goals/{id}/checklist` 支持禁排占位项
  补参（量化 subject/slot 后该项从「恒不通过」恢复参与验收）；每次保存把旧清单
  快照进 `solve_goals.checklist_history`（`[{version, saved_at, saved_by, items}]`，
  迁移 `d7f2a9c4b8e1`）；当前版本号 = `checklist_version`（历史长度+1，初始 v1），
  目标详情可展开历史版本只读回看。

### 一句话解析流式接口（SSE）

`POST /assistant/interpret/stream` 是 `/assistant/interpret` 的流式版本：请求体、鉴权
（`Authorization: Bearer <JWT>`）、课表方案头和业务语义完全一致，响应改为
`text/event-stream` 逐事件下行，并附带 `X-Accel-Buffering: no`（防反代缓冲）。

事件序列（`event:` 行 + 单行 `data:` JSON，帧间空行分隔）：

| 事件 | data | 说明 |
| --- | --- | --- |
| `stage` | `{"stage":"connect\|read\|validate"}` | 解析阶段推进；`connect` 为首包，连接建立后立即发送（兼作心跳/连接确认） |
| `thinking` | `{"delta":"…","elapsed":0.42}` | 模型思考增量（`reasoning_content` 与 `<think>` 块内容），`elapsed` 为开始解析后的秒数 |
| `result` | 完整 `AssistantInterpretResponse` JSON | 与同步接口响应同构（含 `thinking` 全文）；仅此事件后连接正常结束 |
| `error` | `{"detail":"…"}` | 流开始后的任何失败（模型输出非 JSON、范围校验 422、上游错误 502 语义等）；`detail` 即同步接口的错误文案 |

约定与降级语义：

- AI 未配置且无 Aily 时，连接建立前直接返回 `409`（JSON，与同步接口同文案），不会进入 SSE；
- Aily 引擎无流式能力，走伪流式：只发 `stage: read/validate` + 单条 `result`，`thinking` 为 `null`；
- OpenAI-compatible 通道请求带 `stream: true` 与 `stream_options.include_usage`，客户端断开时
  后端取消上游模型请求（httpx 流随之关闭）；
- 前端以 fetch reader 手写读帧（`EventSource` 不支持 POST），流式失败（网络、非 200、

- 该端点为手写 SSE 契约，不进 orval 生成钩子。

## 总览分析

`GET /overview/analytics` 为排课助手首页的「数据概览」提供四组只读统计：

1. `teacher_workload`：按校区+教师标识隔离的总课次、总小时、Top 5 和负荷区间；
2. `room_heatmap`：原始星期×课节明细，以及固定 7×3（周一至周日×上午/下午/晚自习）
   的占用教室数、可用教室数、占用率；
3. `optimization_penalties`：最近求解的目标值、界、求解范围内的软规则扣分和满足率，
   并返回分项来源、范围来源和目标值对账差额；
4. `sync_health`：窗口内同步成功/失败、读写量、重试数、平均耗时和最近同步时间。

`date_from`/`date_to` 控制课表统计区间；`sync_window_hours` 控制同步遥测窗口（默认 24 小时）。
没有发布版本或没有可归因软规则数据时返回空明细/说明，不编造指标。

## 记忆层（偏好库）

偏好条目按课表方案隔离（`X-Schedule-Set-Id`），设计与红线见
`docs/roadmap/02-agent-memory.md` §3、§6。谓词白名单：`avoid_slot`、`prefer_slot`、
`avoid_room`、`prefer_room`、`consecutive_sessions`、`max_daily_load`（后者暂无求解路径，
只登记不进目标函数）。

| 方法 | 路径 | 权限 | 说明 |
| --- | --- | --- | --- |
| GET | `/memory/preferences` | 已登录 | 偏好列表；过滤参数 `subject_type`、`subject_id`、`status` |
| POST | `/memory/preferences` | 管理员/排课员 | 手工登记偏好；`source` 仅允许 `explicit_stated`/`admin_directive` |
| PATCH | `/memory/preferences/{id}` | 管理员/排课员 | 修订 `weight`/`predicate`/`constraint`/`valid_until`；`scope` 以合并方式写入 `constraint`；编辑后重算同组冲突标（MEM-D1） |
| POST | `/memory/preferences/{id}/transition` | 管理员/排课员 | `action=transition`（默认）做状态机迁移 `confirmed`/`rejected`/`expired`，可选 `target_modality`；`target_status=rejected` 时建议带 `rejection_reason`（拒绝原因五选，落拒绝记录；缺省「其他」，前端必填）；`target_status=expired` 可带 `supersedes=<替代它的条目 id>`（provenance 记 `superseded_by`，MEM-D1「以新替旧」裁决）；`action=authorize_trial` 做授权试用（`trial_days` 默认 30，仅 `probation` 条目，条目保持 `probation`；若该候选带冲突标则视为对冲突的显式裁决——旧新并存，MEM-D1） |
| POST | `/memory/preferences/{candidate_id}/adjudicate-replace` | 管理员/排课员 | 「以新替旧」**原子裁决**（MEM-E3）：同一事务内完成 旧条目 `expired`（provenance 记 `superseded_by`/`superseded_at`）→ 候选 `confirmed`（provenance 记 `supersedes`）→ `refresh_conflict_flags` 重算 → 审计 → commit。body 可选 `old_entry_id`（缺省取候选的唯一活跃冲突对端，多于一对时 422 要求显式指定）与 `rejection_reason`（五选，缺省 `other`，记录退场原因）。任一步校验失败整体回滚、旧条目保持原状；重复调用幂等（候选已 `confirmed` 且旧条目已 `expired` 且 provenance 互链 → 200 + `detail=already_applied`，不做二次变更）；响应返回 `{candidate, old_entry, detail}`。保留旧弃新不需要本端点（单次 reject 即可，事务天然成立） |
| POST | `/memory/preferences/{id}/convert-to-rule` | 管理员 | 把 `modality=hard` 条目转成正式 Rule（`hardness=hard`，kind 对齐 constraint-catalog）；`source_doc=memory:<entry_id>` 回链，条目转 `expired` 且 provenance 记 `rule_id`；induced 来源必须传 `confirmed_conversion=true`，否则 422 |
| POST | `/memory/mining-runs` | 管理员/排课员 | 回顾近期调课事件归纳偏好候选，返回落库后的候选清单（`skipped_rejected` 计入被拒绝记忆拦下的候选数；事件先经「可学习事件」公共前置筛选，MEM-D1） |

约定与红线：

- **三态拆分（MEM-C1）**：待确认候选（`probation` 且未授权试用）不进求解输入；
  「授权试用」后以试用期衰减权重小步参与、`trial_until` 到期自动退出；`confirmed`
  全量权重。无感采集，不无感改变排课。
- 创建偏好不传 `valid_until` 时，后端默认取**本方案主数据最大上课日期**（方案内没有
  课次时回落「当前日期 + 180 天」）并在响应中回显；过期作废不删除。
- `POST /memory/preferences` 创建的条目 `status=confirmed`；挖掘产生的条目 `source=induced_from_adjustment`、
  `status=probation`、`confidence=0.5`、`weight=40`，确认后才以全量权重参与求解。
- **红线**：`induced_from_adjustment` 条目请求升为硬约束（`target_modality=hard`）一律 `422`；
  转正式规则必须经 convert-to-rule 显式确认。硬约束只能来自教务显式声明或管理员指令。
- `modality=hard` 的条目不参与偏好编译；编译逐条标记 `hard_requires_conversion`
  （已转换则标 `converted_to_rule`），由管理员走 convert-to-rule。
- 条目的 `valid_from`/`valid_until` 是**生效日期窗口**：随编译进入规则 scope，偏好
  只约束 `lesson_date` 落在窗口内的课次；登记状态的过期判断（今天 vs valid_until）
  与窗口作用范围是两件事。constraint 内日期窗口与条目级有效期取**交集**为实际
  生效窗口；交集为空（MEM-F/F1）→ 该条目编译按 `not_applicable` 处理，且
  `resolve_conflicts_for_new_entry` 对它直接返回 `not_applicable`——**不触发
  替代/冲突/相邻任何分支、不改动任何旧条目**（「永远不会生效」的新条目无论
  什么状态都不能让有效旧偏好退出）。
- 状态机：`probation → confirmed/rejected/expired`；`confirmed → expired/rejected`；`rejected`、`expired` 为终态。
- 挖掘：可学习事件先经**公共前置筛选**（MEM-D1 D3，AI 与统计共用，模型有无配置
  不改变业务边界）：方案内 + **最近 90 天**滚动窗口（上限 200 条）+ 候选未被取消
  或拒绝（事件模型的稳定负向终态为 `candidate_discarded`）+ `declared_reason`
  非临时被迫类。配置 AI 走模型归纳（模型只提名，可整轮弃权并可输出 `reasons`
  自述失败原因；提示词注明输入已预筛，不要求模型自行过滤）；
  代码做**两道校验（MEM-C2）**：①结构校验——约束里的时段/教室/日期必须来自候选
  引用的证据事件（时段在事件 `slot_business_ids` 内、教室按事件 `room_business_id`
  口径——调课事件载荷无 before/after 快照、日期落在事件 `date_from~date_to` 内）；
  ②证据校验——至少 2 条不同证据，且每条证据事件的主体与候选主体一致（李老师的
  事件不能支持张老师的候选）。未配置或调用失败自动退化为确定性统计；同主体+
  同类型+**同归因类**调课 ≥2 次才产生候选，候选文案为「发现 N 次相似调整，
  建议教务确认是否存在长期需求」。同 `subject_type+subject_id+predicate+constraint`
  已存在 `probation`/`confirmed` 条目时跳过去重。候选 constraint 自带日期窗口时，
  条目级默认有效期取**覆盖该窗口的最小范围**（不得比 constraint 窗口更宽；
  无日期维持「今天 +180 天」，MEM-D1 D2）。
- **拒绝记忆（MEM-C2）**：transition 到 `rejected` 落 `preference_rejections`
  （签名 = 主体+谓词+约束规范化 JSON；`evidence` 存被拒证据 id 集合）。再挖掘时
  同签名候选证据 ⊆ 已拒证据 → 跳过（`skipped_rejected`）；含实质新证据 → 允许重提，
  条目 provenance 带 `previously_rejected`（前端显示「此前被拒：<原因>」amber 徽标）。
- **矛盾消解（MEM-C2 / MEM-D1）**：创建/挖掘落库时对同主体同谓词旧活跃条目三分支：
  `new_replaces`（生效窗口不重叠且不相邻，**且新条目已获授权** → 旧条目 `expired`，
  provenance 记 `superseded_by`；未授权候选与旧条目窗口错开时并存不动）；
  `time_sliced`（相邻不重叠 → 并存，编译的日期窗口互不越界）；
  `conflict_flagged`（窗口重叠且约束互斥——`prefer_*` 目标集不相交或数值谓词取值
  不同，`avoid_*` 恒兼容 → **候选提出冲突**）。
- **冲突只由候选提出、裁决是显式操作（MEM-D1 D1）**：`conflict` 是候选侧
  `proposed_conflict` 标，只落在提出方（组内较新条目）上；被点名的旧 confirmed
  条目**照常编译**（outcome=applied），其编译参与度永不因未授权候选而改变。
  提出方已 confirmed/授权试用时编译期跳过（outcome=`conflict_unresolved`，不进
  求解输入），前端 amber 徽标提示。裁决三动作：①**保留旧弃新** = 候选
  `rejected`（带 `rejection_reason`，走既有 transition 端点）；②**以新替旧** =
  `POST /memory/preferences/{candidate_id}/adjudicate-replace`（MEM-E3 原子裁决：
  同一事务内旧条目 `expired`+`superseded_by`、候选 `confirmed`+`supersedes`、
  冲突重算、审计；失败整体回滚、重复请求幂等）——旧的「旧条目 transition
  `expired`+`supersedes` 后候选再 `confirmed`」两步请求已被本端点取代，避免
  第二步失败时出现「旧的已退场、新的没生效」的中间态；③**授权试用** =
  `action=authorize_trial`（旧新并存：旧全权、候选试用期小权重；provenance 记
  `conflict_resolved_with`）。
  `refresh_conflict_flags` 是创建/编辑/确认/失效/拒绝/授权试用共用的唯一冲突
  重算入口：标记按「落提出方」重算，日期窗口不相交不算冲突（D2），对方离开活跃集
  或已显式裁决共存时自动清标；`PATCH /memory/preferences/{id}` 编辑后同样触发。
- **两层日期取交集（MEM-D1 D2）**：编译窗口 = constraint 内 `date_from/date_to`
  与条目级 `valid_from/valid_until` 的**交集**；交集为空 → outcome=`not_applicable`
  （明确不适用），条目不进编译。
- **求解联动（创建时冻结，MEM-C1）**：创建求解任务时即把条目快照、编译后的内部软规则、
  逐条使用结果（`applied`/`not_authorized`/`expired`/`unsupported_predicate`/
  `converted_to_rule`/`hard_requires_conversion`/`conflict_unresolved`/`not_applicable`/
  `compile_error`）冻结进
  `DataSnapshot.payload["memory"]` 与 `SolverRun.memory_usage`；执行只读快照，事后改记忆
  不影响在途求解的可复现性。目标权重 = `weight × (confirmed?1.0:0.3 授权试用衰减) × confidence`；
  偏好永远是软约束，不会造成无解。编译整体失败时 `memory_usage.status=compile_failed`，
  求解照常但解释事实包与前端解释面板必须显示「本次未使用偏好记忆：编译失败」；
  正常时显示「本次参考 N 条偏好记忆（已应用 X / 未使用 Y 及原因）」。
- 调课范围：`POST /reschedule-events` 带 `course_business_id` 时范围就是这一节课（配合 `date_from`/`date_to` 限定到具体日期），不因教师/教室相同扩大；`include_neighbors`（默认 true）控制是否把前后 `neighborhood_days` 天内同班/同教室课次纳入可挪动范围；课次不在父课表或日期范围内 → 422。事件状态：`pending` → `candidate_ready` / `no_candidate`（无可行候选）/ `failed`（求解失败）。
- 调课归因：`POST /reschedule-events` 请求体支持可选 `declared_reason`（≤80 字），
  落库于 `reschedule_events.declared_reason` 并在响应中回显，供偏好挖掘消噪（前端归因 chips 属 MEM-B）。

| GET | `/schedule-sets/{id}/public-links` | 链接列表：`token_hint`（末 4 位）、状态（`active`/`expired`/`revoked`）、访问数与最后访问时间、范围与展示名；**任何响应都不回传明文 token** |
| POST | `/schedule-sets/{id}/public-links` | 创建链接。body：`scope`（`class`/`teacher`/`school`）、`campus_id`、`resource_business_id`、`display_name?`、`expires_at?`、`show_teacher_names?`（默认 true）、`note?`；创建时校验目标存在（class 查 ClassGroup、teacher 查 Teacher，school 不绑定资源）。**响应（201）唯一一次返回明文 `token` 与完整 `public_url`**（`{frontend_url}/public/t/{token}`） |
| POST | `/schedule-sets/{id}/public-links/batch` | 按当前发布版本（public_class_index）为全部班级批量创建 class 链接：校验、默认有效期与审计沿用单条创建；响应**唯一一次**返回全部明文 `[{display_name, url, token}]` 与失败清单 `[{campus_id, class_business_id, class_name, detail}]`（单班失败不中断） |
| POST | `/public-links/{link_id}/rotate` | 轮换：旧 token 立即置 `revoked`，新建一条并返回新明文；已停用链接 409 |
| DELETE | `/public-links/{link_id}` | 停用（置 `revoked` 软删），204 |

token 为 `secrets.token_urlsafe(32)`（256-bit 熵），库内只存 SHA-256 哈希；审计日志只落 `token_hint`。

### 公开（免登录，无 JWT）

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/public/links/{token}/schedule.json` | class/teacher 范围返回课表白名单 payload（班级名/科目/课节名/教师姓名/教室/日期时间 + 调课通知 `adjustments` + `version_no`/`published_at`/`first_date`/`last_date`）；school 范围返回班级索引（督导公示）。响应为显式 Pydantic 白名单，**无学生字段、教师工号、校区内部主键** |
| GET | `/public/links/{token}/class/{campus_id}/{class_business_id}/schedule.json` | school 目录链接下钻到单个班级的公开 payload（同 class 链接的 schedule.json 白名单口径）；仅 school scope token 有效，其他 scope/伪造/过期同形 404 |
| GET | `/public/links/{token}/calendar.ics` | ICS 订阅日历。`Cache-Control: public, max-age=3600`；`ETag = sha256(version_id + published_at)`，`If-None-Match` 命中返回 304 |

安全与语义约定：

- **404 同形**：伪造、过期、停用（以及 `PUBLIC_LINKS_ENABLED=false`）一律相同 404，
  不暴露 token 存在性；有效 token 不做限流（日历轮询器依赖反复拉取）。
- `show_teacher_names=false` 的链接：payload 教师姓名列表为空，ICS 不含 DESCRIPTION。
- 访问计数节流：命中后更新 `last_seen_at`/`access_count`，10 分钟内的重复拉取只记一次。
- ICS：有 `lesson_date` 的课次生成普通 VEVENT；循环课次（无 `lesson_date`、只有 `TimeSlot.weekday`）生成 `RRULE:FREQ=WEEKLY;BYDAY=XX;UNTIL=窗口末` 的 VEVENT（`DTSTART` 取窗口内首个匹配该 weekday 的日期 + 时段；窗口 = 当前发布版本有日期课次的 min/max，无锚点回退今天−7 ～ +60 天）。**已知取舍**：RRULE 无法表达单次调课 override，时效性由 H5 调课横幅（`adjustments`）兜底；UID
  `tupai-{scope}-{resource_business_id}-{assignment_id}@public.tupai` 跨版本稳定，
  `DTSTART/DTEND;TZID=Asia/Shanghai`（静态 VTIMEZONE，+0800 无夏令时）、
  `DTSTAMP=published_at(UTC)`、`SEQUENCE=version_no`；重新发布后 ETag/DTSTAMP 变化，
  客户端原位更新。
- 部署前提：公网可达 + HTTPS（Google 日历订阅不支持认证）。

## 常见状态码

- `401`：JWT/Aily 密钥无效；
- `403`：角色或课表方案权限不足；
- `404`：当前方案内对象不存在；
- `409`：状态冲突、引用冲突、配置/授权未就绪或飞书服务错误；
- `422`：字段、日期范围、业务实体或请求结构不合法；
- `502`：飞书/AI 上游网络或响应错误。
